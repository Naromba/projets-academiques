Protocole Selective Repeat avec Bit-Stuffing HDLC

Architecture generale

Le protocole est compose de 4 classes interconnectees :

  • Frame : Classe - Trame HDLC encapsulee avec CRC-16 et bit-stuffing
  • Sender : Classe - Emetteur Selective Repeat (fenetre=4, timers individuels, ACKs cumulatifs)
  • Receiver : Classe - Recepteur avec buffer circulaire et ACKs cumulatifs
  • Canal : Classe - Simulation du lien (pertes, erreurs, delais aleatoires)

Module auxiliaire : stuffing.py - Codeur bit-stuffing HDLC

Frame (Trame HDLC)

Represente une unite de transmission atomique.

Attributs : seq, acknum, is_ack, payload, length, crc

Processus : Donnees -> Bit-stuffing -> Encadrement 0x7E

Taille : payload <= 100 octets

Sender (Emetteur SR)

Implemente Selective Repeat avec fenetre de 4.

Logique :

  • Segmente message en chunks <=100 octets
  • Cree frames avec seq modulo 8
  • Envoie avec timers individuels
  • Retransmet si timeout >= timeout_ms

ACKs : Cumulatifs (ACK n = toutes frames 0..n OK)

Receiver (Recepteur SR)

Gere la livraison en ordre des donnees.

Buffer circulaire : Taille = 4, modulo 8

Livraison : En-ordre uniquement

ACKs : ACK(expected-1) cumulatif

Sortie : message_bytes() = message reconstruit

Canal (Simulation reseau)

Simule les imperfections du lien physique.

3 defauts :

  • Perte (probPerte) : trame jamais livree
  • Erreur (probErreur) : bit-flip (corruption CRC)
  • Delai (delaiMax) : latence aleatoire 0..delaiMax ms

Scenarios : Parfait, Bruite, Instable

stuffing.py (Module - Bit-stuffing HDLC)

Module avec fonctions.

Fonctions principales :

  • bytes_to_bits(data) : convertit octets -> bits
  • bits_to_bytes(bits) : convertit bits -> octets
  • bit_stuff(bits) : insere un 0 apres 5 bits a 1
  • bit_destuff(bits) : retire les 0 de bourrage

Flags : 0x7E encadre chaque trame

Flux de communication

Donnees (Sender -> Receiver) :

  • message.txt (6400 octets)
  • -> Segmentation en 100 octets
  • -> 65 Frames creees (seq 0..64)
  • -> Envoi via Canal
  • -> Reception + verification CRC
  • -> Reconstruction en-ordre

ACKs (Receiver -> Sender) : Cumulatifs, en-ordre

Exemple de flux complet

ETAPE 1 : INITIALISATION - message.txt : 6400 octets - MAX_PAYLOAD : 100 octets/frame - MOD : 8 (numerotation modulo 8) - W : 4 (fenetre Selective Repeat) - TIMEOUT_MS : 260 ms (doit etre > delaiMax) ETAPE 2 : SEGMENTATION (Sender.send_message) - chunks = [data[i:i+100] for i ...] - 65 chunks de <= 100 octets crees ETAPE 3 : ENVOI (boucle SR) 1. Sender cree : Frame(seq=2, payload=100 bytes) + CRC-16 2. Bit-stuffing applique 3. Encadrage avec flags 0x7E 4. Envoi via Canal 5. Canal : simule delai, perte ou erreur 6. Receiver : recoit -> destuffing -> verif CRC -> Buffer[2] 7. Receiver : si seq 0,1,2 continus -> rebuild += payload 8. Receiver : expected = 3 -> Envoie ACK(acknum=2) 9. Sender : recoit ACK -> libere frames 0,1,2 -> base = 3 ETAPE 4 : TIMEOUT/RETRANSMISSION - Si timeout >= 260 ms -> Sender._on_timeout() - Retransmet Frame(seq=i) avec nouveau timer - Receiver peut recevoir en-desordre - Si CRC OK, buffer et attendre sequence - Livraison reste en-ordre ETAPE 5 : RECONSTRUCTION/SORTIE - rebuilt = chunk0 + chunk1 + ... + chunk64 - message_bytes() -> 6400 octets identiques au depart - Integrite message : SUCCES
